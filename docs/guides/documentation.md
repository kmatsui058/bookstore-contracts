# ドキュメント作成ガイドライン

_[ガイドラインに戻る](./README.md)_

このリポジトリのドキュメント（`docs/` 配下の Markdown）を書くときの取り決めです。

## 守ること

- 冒頭に、このガイドラインに準拠することを書く。特定分野のガイドライン（モデリング・要件・仕様書管理）があれば、それも書く
- H1 は簡潔にし、その直後にドキュメントの位置づけを書く
- 親の README.md から子のドキュメントへリンクし、子のドキュメントには `_[戻る](../README.md)_` の形で親へのリンクを置く
- 同じ情報は1箇所にだけ書き、ほかからはリンクする（SSOT）
- ドメインモデルで定義された語を使い、定義されていない語を使わない
- Markdown は4スペースでインデントする

## リンク

- `docs/` をルートとした `/` 始まりの絶対パスに、拡張子 `.md` を付けて書く（例: `/guides/domain-modeling.md`）
- 相対パスは、直近の親への `_[戻る](../README.md)_` と、OpenSpec の change の中の自己参照（change はディレクトリごと移動するため）にだけ使う
- LikeC4 のビューへは、そのページからサイトの `c4/` への相対パスに `#/view/<ビューID>/` を付けてリンクする（例: トップページからは `c4/#/view/index/`）。`/` 始まりにすると、サイトの公開パスが変わったときに壊れる
